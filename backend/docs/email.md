# Отправка писем

Backend использует **Unisender Go** (транзакционный HTTPS API). Переменные
SMTP_HOST/PORT/USER/PASS в этом коде не используются.

В корневом `.env`, рядом с используемым `docker-compose.yml`, задать:

```dotenv
UNISENDER_API_KEY=ключ_транзакционного_API_Unisender_Go
```

Файл `backend/.env` при production Docker-сборке в образ не копируется.
Compose передаёт значение из своего окружения/корневого `.env` через
`environment.UNISENDER_API_KEY`. Ключ не выводить в логах и не коммитить.
В Unisender Go должен быть подтверждён отправитель `platformaapp@platformaapp.ru`.

Для compose этого репозитория, из каталога с compose-файлом:

```sh
docker compose up -d --build --force-recreate backend
```

Если сервер использует другой compose-файл, указать его через `-f` и
использовать имя его backend-сервиса. Если контейнер запускается через
`docker run`, добавить переменную через используемый `--env-file` и
пересоздать контейнер с прежними портами, сетью и mounts. Обычный
`docker restart` не обновляет переменные окружения контейнера.

Безопасная проверка для вашего контейнера (не печатает значение ключа):

```sh
docker exec platforma_backend node -e 'console.log("UNISENDER_API_KEY:", process.env.UNISENDER_API_KEY?.trim() ? "задан" : "не задан")'
docker logs --since 15m platforma_backend 2>&1 | grep -E 'Unisender|Password.*email|password.*email|EmailService'
```

При запросе восстановления без настроенного ключа API возвращает 503,
независимо от того, существует ли адрес. Когда ключ настроен, ответ
остаётся одинаковым для существующих и неизвестных адресов. Отправка
ссылки выполняется в фоне, ошибки записываются в логи.

После успешной смены или сброса пароля отправляется отдельное уведомление
«Пароль изменён». Сам пароль в письме не передаётся. Сбой доставки этого
уведомления не отменяет уже изменённый пароль.

`job_id` означает принятие сообщения провайдером, а не гарантированное
попадание во «Входящие». Если API принял письмо, но адресат его не получил,
проверить статус доставки в Unisender Go и ответ почтового сервера адресата.

Старые SMTP-учётные данные удалены из compose. Ранее записанный в репозитории
SMTP-пароль следует заменить у почтового провайдера; удаление строки не
удаляет его из истории Git.

Проверки без отправки реальных писем:

```sh
npm test -- --runInBand password-email.spec.ts email.service.spec.ts
```
